---
title: "Devis des frais de transaction"
description: "Calculer le montant des frais, le montant payable et le porteur des frais avant une transaction."
openapi: "POST /transactions/fees/quote"
---

Cette route calcule les frais cote serveur avant de lancer une collection ou un disbursement.

Vous pouvez identifier le service avec `serviceId`, `service_id`, `provider`, `serviceCode` ou `service_code`.

Pour une application API directe, le porteur des frais vient de la configuration de l'application authentifiee ou du header interne `X-SP-Fee-Bearer`.

Pour un plugin, envoyez `origin: "PLUGIN"` et fournissez `feeBearer` dans le payload ou dans la query string. Le payload est prioritaire.

| Champ | Role |
| --- | --- |
| `amount` | Montant de base a facturer |
| `amount_unit` | Champ JSON facultatif à la racine : `MAJOR` par défaut, ou `MINOR` pour des centimes entiers USD/EUR |
| `currency` | Devise attendue par le service |
| `operation` | `COLLECTION` par defaut, ou `DISBURSEMENT` |
| `provider` | Code service, par exemple `mtn_cmr` |
| `origin` | `APPLICATION` par defaut, ou `PLUGIN` |
| `feeBearer` | `CUSTOMER` ou `MERCHANT` |

Lorsque `feeBearer` vaut `CUSTOMER`, `payableAmount` inclut les frais. Lorsque `feeBearer` vaut `MERCHANT`, `merchantNetAmount` indique le montant net marchand apres frais.

Envoyez `amount` en valeur réelle par défaut : `4.01` pour 4,01 USD/EUR. Les clients API qui envoient déjà des centimes peuvent préciser `amount_unit: "MINOR"` à la racine du corps JSON, au même niveau que `amount` et `currency`, et non dans `metadata`. Les réponses publiques reviennent en valeur réelle même si la requête utilise `MINOR`. Consultez [les montants et devises](/api-docs/monetary-units).

`baseAmount`, `feeAmount`, `payableAmount` et `merchantNetAmount` sont retournés en valeur réelle. Conservez leurs décimales pour les afficher ou les comparer.
