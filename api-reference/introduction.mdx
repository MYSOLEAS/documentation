La reference API de Mysoleas est organisee autour de l'infrastructure commune et des corps de metier.

| Couche | Serveur | URL | Role |
| --- | --- | --- | --- |
| Infrastructure | Gateway | `https://api.mysoleas.com` | Route les appels vers les services metier |
| Infrastructure | Mysoleas Identity Cloud | `https://account.mysoleas.com` | OAuth2/OIDC, bouton **Se connecter avec Mysoleas**, gestion utilisateur, JWT et userinfo |
| Metier | SoleasPay | via `api.mysoleas.com` | Paiements, liens, souscriptions, collections, disbursements, pays, services et providers |

Mysoleas Identity Cloud peut etre integre seul pour gerer l'authentification et les utilisateurs d'une application tierce. Dans ce cas, votre application utilise `account.mysoleas.com`, valide le JWT, lit `userinfo`, puis continue avec ses propres APIs.

Pour creer une application OAuth2, connectez-vous au dashboard Mysoleas:

```txt
https://mysoleas.com
```

Les routes gateway protegees utilisent le header suivant:

```txt
x-sp-auth-token: Bearer <access_token>
```

Le token est un JWT emis par Mysoleas Identity Cloud.

<Note>
  Les endpoints OAuth2 eux-memes vivent sur `account.mysoleas.com`. Les plugins SoleasPay v3 utilisent une `apikey` marchand et ne demandent pas ce header.
</Note>

Les routes publiques de paiement par lien sont:

- `GET /pay/{shortCode}`;
- `POST /pay/{shortCode}/pay`.

## Format de succes

```json
{
  "code": 200,
  "success": true,
  "data": {},
  "locale": "fr",
  "message": "transaction_submitted"
}
```

## Format d'erreur

```json
{
  "success": false,
  "code": 400,
  "message": "empty_data"
}
```

## Pagination

Les listes acceptent generalement `page` et `limit`. La reponse peut contenir `meta.pagination`.

```json
{
  "pagination": {
    "page": 1,
    "limit": 25,
    "total": 120,
    "pages": 5,
    "has_next": true,
    "has_previous": false
  }
}
```
