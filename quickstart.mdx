---
title: "Demarrage rapide"
description: "Le chemin le plus court pour creer une application dans SoleasPay, obtenir un token gateway et lancer une premiere transaction."
---

Ce guide vous accompagne depuis la creation d'une application dans SoleasPay jusqu'au suivi d'une premiere transaction.

<Note>
  Mysoleas Identity Cloud gere l'authentification et les utilisateurs de vos applications. Il ne remplace pas l'application creee dans SoleasPay qui fournit les credentials API pour consommer la gateway.
</Note>

## 1. Preparez vos domaines

Toutes les requetes metier protegees partent vers la gateway.

```txt
https://api.mysoleas.com
```

Les parcours utilisateurs OAuth2/OIDC partent vers Mysoleas Identity Cloud.

```txt
https://account.mysoleas.com
```

<Tip>
  Stockez ces URLs dans des variables d'environnement. Cela rend vos tests, vos workers et votre backoffice plus faciles a maintenir.
</Tip>

## 2. Creez une application dans SoleasPay

Avant d'appeler les endpoints gateway, creez une application dans SoleasPay depuis votre espace marchand. Cette application represente votre integration API.

Conservez les deux credentials generes:

| Credential | Role |
| --- | --- |
| `sp_client_id` | Identifie l'application creee dans SoleasPay |
| `sp_client_secret` | Secret serveur utilise pour obtenir un token gateway |

<Warning>
  Ne mettez jamais `sp_client_secret` dans un frontend, une application mobile ou un depot public. Il doit rester cote backend.
</Warning>

## 3. Obtenez un token gateway

Utilisez les credentials de l'application creee dans SoleasPay.

```bash
curl -X POST "https://account.mysoleas.com/oauth/token" \
  -H "Content-Type: application/json" \
  -d '{
    "sp_client_id": "YOUR_SOLEASEPAY_APP_CLIENT_ID",
    "sp_client_secret": "YOUR_SOLEASEPAY_APP_CLIENT_SECRET"
  }'
```

La reponse contient un `access_token`. Ce token represente l'application creee dans SoleasPay et se transmet a la gateway.

```json
{
  "access_token": "eyJ...",
  "token_type": "Bearer",
  "token_expired_at": 1785259148
}
```

<Tip>
  Le token obtenu ici sert aux appels API gateway. Le JWT utilisateur issu de **Se connecter avec Mysoleas** sert a ouvrir une session utilisateur dans votre propre application.
</Tip>

## 4. Appelez la gateway

Transmettez le jeton dans `x-sp-auth-token`.

```bash
curl "https://api.mysoleas.com/service/list?country=CMR&currency=XAF" \
  -H "x-sp-auth-token: Bearer YOUR_ACCESS_TOKEN" \
  -H "Accept: application/json"
```

Vous pouvez aussi transmettre des headers de contexte lorsque votre application gere plusieurs environnements ou pays.

| Header | Usage |
| --- | --- |
| `x-sp-auth-token` | Token Bearer obtenu depuis une application creee dans SoleasPay |
| `X-Request-Id` | Identifiant de trace cote marchand |
| `X-Idempotency-Key` | Cle d'idempotence explicite pour les operations sensibles |
| `X-SP-Country` | Pays actif, par exemple `CMR` |
| `X-SP-Environment` | Environnement logique, par exemple `prod` ou `dev` |

## 5. Choisissez un service

Listez les services disponibles avant de creer une transaction. Le champ `code` du service devient la valeur `provider` dans les payloads de paiement.

```bash
curl "https://api.mysoleas.com/service/list?country=CMR&currency=XAF" \
  -H "x-sp-auth-token: Bearer YOUR_ACCESS_TOKEN"
```

Un service utilisable pour une collection doit avoir `is_active: true` et `is_can_collect: true`.

Un service utilisable pour un disbursement doit avoir `is_active: true` et `is_can_disburse: true`.

## 6. Lancez une collection

Le flux standard se fait en trois appels: `intent`, `execute`, puis `status`.

```bash
curl -X POST "https://api.mysoleas.com/collection/intent" \
  -H "x-sp-auth-token: Bearer YOUR_ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "amount": 2500,
    "currency": "XAF",
    "transaction_uuid": "2f8b9a68-1ad3-4a0c-a187-40b91a4c44a1",
    "provider": "mtn_cmr",
    "channel": "PROVIDER",
    "customer_wallet": "670000000",
    "description": "Commande MS-10045"
  }'
```

<Note>
  Dans la requete, `customer_wallet` ne doit pas contenir l'indicatif du pays.
</Note>

La reponse contient `transaction_reference`. Utilisez cette valeur pour executer et suivre la transaction.

```bash
curl -X POST "https://api.mysoleas.com/collection/execute" \
  -H "x-sp-auth-token: Bearer YOUR_ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "transaction_reference": "TRX-20260728-000001",
    "invoice_reference": "MS-10045"
  }'
```

## 7. Suivez le statut

Interrogez le statut jusqu'a obtenir un etat final.

```bash
curl -X POST "https://api.mysoleas.com/collection/status" \
  -H "x-sp-auth-token: Bearer YOUR_ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "transaction_reference": "TRX-20260728-000001"
  }'
```

Les etats finaux sont `COMPLETED`, `SUCCESS`, `FAILED`, `CANCELLED` et `REFUNDED`.
